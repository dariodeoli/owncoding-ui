# Adoptar el sistema v2 (tokens + iconos) — guía para las apps

Los tokens v2 del piloto y los iconos de categoría están **publicados en
`owncoding-ui` v0.11.0**. Esta guía es el paso a paso para que una app (MobOS
primero; después ScaleOS, LedBox y PagaYa) los consuma sin bloques locales.

Referencias: `docs/REGLAS.md` §8 bis (props de los objetos), README (instalación
y versiones), CHANGELOG (qué entró en cada release).

## 1. Tokens v2 (lenguaje "device ops")

**Qué es:** base consola (oscura en modo oscuro, equivalente clara en modo
claro), verde **pass** para lo certificado y azul **acción** para lo operativo.
Se aplica **por clase** al contenedor de la pantalla piloto; el resto de la app
sigue con su paleta hasta que se migre a propósito.

| Token | Claro | Oscuro (`html.dark`) |
| --- | --- | --- |
| Fondo (`--c-paper`) | #F6F8FB | #0E1116 |
| Superficie (`--c-ink`) | #FFFFFF | #1F2430 |
| Borde (`--c-ink-600`) | #D6DCE6 | #373F51 |
| Texto (`--c-fore`) | #0E1116 | #F4F6FA |
| Ok / pass (`--c-ok`) | #166534 | #4ADE80 |
| Falla (`--c-bad`) | #B91C1C | #FCA5A5 |
| Atención (`--c-warn`) | #92400E | #FCD34D |
| Acción (`--c-info`) | #2059BE | #9FB8FF |

Los tonos semánticos son los de **texto AA** (medidos sobre el shell v2 en
#241): los vivos de PhoneCheck (#22C55E, #DC2626, #D97706, #4D7CFE) quedan para
rellenos e indicadores — siguen disponibles en `--c-pass`/`--c-accion` y en las
clases `bg-*`. El armado del shell con sus reglas está en **`docs/SHELL.md`**;
la guarda `test/contraste-tokens.test.js` fija el 4.5:1.

Pasos:

1. `npm install github:dariodeoli/owncoding-ui#v0.11.0` y usar el preset
   (`owncoding-ui/tailwind-preset`) para que existan `pass`, `accion`, `fono`,
   `ink-*`, etc.
2. Importar los estilos **después** de las directivas de Tailwind:
   `@import 'owncoding-ui/styles.css';`
3. Poner la clase del scope en el contenedor de la pantalla:
   ```jsx
   <div className="tema-v2">…</div>
   ```
   El alias `.v2-piloto` sigue funcionando: las pantallas que ya lo usan no
   cambian el markup, solo se borra el bloque local de `index.css` cuando la app
   importe la biblioteca. Con `styles.css`, el scope ya trae las **reglas del
   shell** (ítem activo AA, rótulos de grupo, chips `.v2-chip`, foco por tema)
   y `NavLateral` ofrece grupos plegables: ver `docs/SHELL.md`.
4. Números grandes (contadores, tableros, "x de y pass"):
   ```jsx
   <p className="text-3xl font-bold v2-numero">3 de 3 pass</p>
   ```
5. Colores semánticos en las clases: para **texto** los tonos AA (`text-ok`,
   `text-bad`, `text-warn`, `text-info`); para **relleno e indicadores** los
   vivos (`bg-pass/10`, `border-accion/30`). **No** volver a definir `--c-*` por
   pantalla ni copiar los hex del piloto.
6. El verde pass y el azul acción existen en **cualquier tema** (`--c-pass`,
   `--c-pass-dark`, `--c-pass-soft`, `--c-accion` en `:root`): se pueden usar
   fuera del scope cuando corresponda (sellos "certificado", CTAs de acción).
7. IMEI/serial: monoespaciada. El objeto `TileEquipo` y los estados ya la
   aplican con `data-serial`; en un campo suelto, `className="font-mono"`.

## 2. Iconos de categoría

**Qué es:** un glifo por categoría de producto (mobile/laptop/tablet/watch/
buds/cable) y el mapa reusable para normalizar el texto libre que ya existe.

```jsx
import { IconoCategoria, CATEGORIAS_PRODUCTO, categoriaDe } from 'owncoding-ui'

// Fila, tarjeta o selector: el icono sale de la categoría o del modelo
<IconoCategoria categoria={product.category || product.model} className="h-5 w-5" />

// Filtros: mismas opciones que la fila (clave + etiqueta + icono)
{CATEGORIAS_PRODUCTO.map(({ clave, etiqueta }) => <option key={clave} value={clave}>{etiqueta}</option>)}

// Migración aditiva: inferir la clave canónica del texto libre actual
const clave = categoriaDe(product.model || product.name || product.category)
```

Categorías canónicas: `iphone`, `macbook`, `ipad`, `watch`, `airpods`,
`accesorios`, `servicio`, `otro`. Reglas de la normalización:

- Un accesorio que menciona un equipo sigue siendo accesorio: **"Funda iPhone
  15" → accesorios** (no iPhone).
- Mayúsculas y acentos no importan: **"CELULAR" → iPhone**, "MacBook Pro 14" →
  MacBook, "Apple Watch" → watch, "auriculares" → AirPods.
- Lo que no se reconoce cae en `otro`; nunca se inventa una categoría.

## 3. Objetos del checklist/rack que acompañan al v2

Si la pantalla es de inspección o consola, usar los objetos publicados (props en
`docs/REGLAS.md` §8 bis) en vez de armar el markup:

- `SemaforoItem` / `FilaChecklist` + `ConteoChecklist` ("x de y pass")
- `ChipEstado`, `ChipsLocks` (iCloud/MDM/ESN/carrier/OEM)
- `MedidorBateria` (barra o chip), `GradoBadge` (A/B/C)
- `TileEquipo` (foto o icono de categoría + IMEI mono + estado + grado +
  batería + locks) y `Stepper` (Intake → Diagnóstico → Borrado → Listo)
- `FichaCertificado` (la tarjeta del informe público: modelo, IMEI enmascarado,
  grado, batería, "x de y pass", locks, quién/cuándo verificó y QR) con
  `CodigoQr` / `qrDataUrl` para el enlace `/u/<serial>`. Necesita `qrcode`
  instalado en la app (peer opcional).
- `VistaPreviaPapel` (preview v2): el documento impreso con el ancho real del
  papel (`thermal-80`/`thermal-58`/`thermal-55`/`a4`) para comprobantes,
  reportes e informe; el selector de formato va con `SegmentedField`.

## 4. Ejemplo completo: migrar una pantalla (fila de inventario)

Caso real (fila de unidades del inventario en MobOS). Se migra **una fila** y
se replica: no se toca la pantalla entera de una.

### Antes (markup actual, sin v2)

```jsx
function FilaUnidad({ unit }) {
  return (
    <div className="grid grid-cols-[1fr_6rem_5rem_7rem] items-center gap-2 border-b border-ink-600 px-3 py-2">
      <span className="min-w-0">
        <b className="block truncate text-[13px] font-semibold">{unit.product?.name}</b>
        <span className="block truncate font-mono text-[10px] text-mute">{ultimos4(unit.serial)}</span>
      </span>
      <span className="truncate text-xs text-mute">{conditionLabel[unit.condition] || '—'}</span>
      <span className="text-xs tabular-nums text-mute">{unit.batteryHealth ? `${unit.batteryHealth}%` : '—'}</span>
      <span className="w-fit rounded border border-ok/30 bg-ok/10 px-1.5 py-0.5 text-[10px] font-bold text-ok">
        {statusLabel[unit.status]}
      </span>
    </div>
  )
}
```

Problemas: el icono del producto no existe (o es genérico), el % de batería no
tiene color por umbral, el chip de estado está copiado a mano y las etiquetas de
estado/condición viven en el archivo (cada pantalla las redefine distinto).

### Después (v2, con los objetos de la biblioteca)

```jsx
import {
  ChipEstado, GradoBadge, IconoCategoria, MedidorBateria, CATEGORIAS_PRODUCTO, categoriaDe,
} from 'owncoding-ui'
// Las etiquetas/tonos de la unidad salen del módulo que ya usa la app:
import { colorCondicionUnidad, estadoInventario, etiquetaCondicionUnidad } from '@/utils/inventario'

function FilaUnidad({ unit }) {
  const estado = estadoInventario(unit)      // { clave, label, tone }
  const bateriaBaja = Number(unit.batteryHealth) > 0 && Number(unit.batteryHealth) < 80
  return (
    <div className="tema-v2 grid grid-cols-[1.5rem_1fr_6rem_5rem_7rem] items-center gap-2 border-b border-ink-600 px-3 py-2">
      <IconoCategoria categoria={unit.category || unit.product?.name || unit.product?.category} className="h-4 w-4 text-mute" />
      <span className="min-w-0">
        <b className="block truncate text-[13px] font-semibold">{unit.product?.name}</b>
        <span className="block truncate font-mono text-[10px] text-mute" data-serial>{ultimos4(unit.serial)}</span>
      </span>
      <span className="truncate text-xs text-mute">{etiquetaCondicionUnidad(unit)}</span>
      <MedidorBateria porcentaje={unit.batteryHealth} variante="chip" />
      <span className="flex w-fit items-center gap-1.5">
        <ChipEstado estado={estado.clave === 'AVAILABLE' ? 'pass' : 'pendiente'} etiqueta={estado.label} />
        {bateriaBaja && <span className="text-[10px] font-semibold text-warn">Batería</span>}
      </span>
    </div>
  )
}
```

Notas del ejemplo:

- `tema-v2` va en el contenedor de la pantalla (no por fila): acá se ve en la
  fila solo para que el ejemplo sea autocontenido.
- El **QR** no aparece en la fila; si la pantalla lo necesita (informe), va con
  `<CodigoQr valor={enlace} />`.
- El **estado** no se decide en la fila: sale de la regla de la app
  (`estadoInventario`), que es la misma que usa la ficha. Esa fue una lección
  del lote 13: una unidad "disponible seminuevo" se veía verde en la ficha y
  naranja en la lista.
- La **condición** usa el mismo trío etiqueta/color/punto
  (`etiquetaCondicionUnidad`, `colorCondicionUnidad`, `puntoCondicionUnidad`).
- Los **importes** siguen saliendo de `Money`/`CeldaMoneda`; los identificadores
  (IMEI/serial) van en `font-mono` + `data-serial`.

### Pasos y verificación (por pantalla)

1. Aplicar `tema-v2` al contenedor y comprobar claro/oscuro.
2. Reemplazar los iconos de producto por `IconoCategoria` (con `categoriaDe`
   como respaldo si el dato viene en texto libre).
3. Cambiar los chips/estados copiados por `ChipEstado`/`Badge` con los tonos
   compartidos.
4. Batería → `MedidorBateria`; grado → `GradoBadge`; checklist → `SemaforoItem`
   / `FilaChecklist` + `ConteoChecklist`.
5. Verificar **densidad y acciones** (nada se pierde: mismas columnas, mismos
   botones), 360/768/1440, tema claro y oscuro.
6. Capturas antes/después y correr lint + tests + build + smoke.

## 5. Checklist de adopción por app

1. Instalar la versión fijada y agregar el preset + `styles.css`.
2. Aplicar `tema-v2` a la primera pantalla piloto y comparar capturas
   antes/después (claro y oscuro, 360/768/1440).
3. Migrar las categorías de producto a las claves canónicas (aditivo, con
   `categoriaDe` como valor por defecto inferido).
4. Reemplazar los iconos predeterminados de producto por `IconoCategoria` en
   listas, tarjetas, filtros y selectores.
5. Borrar los bloques locales de tokens cuando la app ya importe la biblioteca.
6. Correr lint + tests + build + smoke y dejar capturas por fase (regla del
   rediseño v2: nada pierde densidad ni acciones).
